   188→   647→### ⚠️ Cover Content Overflow Prevention (Mandatory)
   189→   648→
   190→   649→1. Cover section page margin is 0; total content height ≤ 15638 twips (1200 twips safety margin for cross-engine compatibility — MS Office renders large fonts taller than calculated).
   191→   650→2. Color block Table `height` must use `rule: "exact"` (never `"atLeast"`).
   192→   651→3. Each recipe code includes height budget annotations — verify during generation.
   193→   652→4. **`verticalAlign` must always be `"top"`**. Never use `"center"` or `"bottom"` in exact-height rows — content will be clipped or overflow. Use `spacing.before` on the first paragraph for vertical positioning.
   194→   653→5. **Title font size MUST be dynamically calculated via `calcTitleLayout()`** (see below). Never hardcode font sizes above 40pt for cover titles. Every recipe MUST call `calcTitleLayout()` before building title paragraphs.
   195→   654→6. **Never use `margins.top`/`margins.bottom` for vertical positioning inside exact-height cells**: Cell margins reduce available height unpredictably across MS Office and WPS. Use `spacing.before` on the first paragraph instead. Only `margins.left`/`margins.right` are safe.
   196→   655→7. **Dynamic spacing is mandatory**: Use `calcCoverSpacing()` to compute `spacing.before` values dynamically based on content element count and title line count. Never use fixed large spacing values (e.g., `before: 4500`) that assume a specific title length.
   197→   656→8. **Cover must be a single-page section**: The cover section must produce exactly ONE page. If content overflows to a second page, it means the height budget is violated. Common overflow causes and fixes:
   198→   657→   - Title font too large → use `calcTitleLayout()` to auto-reduce
   199→   658→   - Too many meta lines → reduce font size or remove less important lines
   200→   659→   - Fixed `spacing.before` values too large → use `calcCoverSpacing()` for dynamic values
   201→   660→   - Subtitle + English label + meta lines combined exceed budget → calculate total and reduce spacing
   202→   661→9. **Cover wrapper table MUST use explicit `allNoBorders`**: The outer 16838 wrapper table and ALL nested tables inside the cover MUST set borders to NONE explicitly. Never rely on docx-js default borders (`single/auto/sz=4`). Default borders add ~8 twips per edge, which causes MS Office to calculate a total height slightly exceeding 16838 → content overflows to a blank page 2. WPS is more lenient but MS Office is strict. **This is the #1 cause of "blank page 2 in MS Office but not in WPS".**
   203→   662→
   204→   663→```js
   205→   664→// ✅ MANDATORY: Define and use allNoBorders for every cover table
   206→   665→const NB = { style: BorderStyle.NONE, size: 0, color: "FFFFFF" };
   207→   666→const noBorders = { top: NB, bottom: NB, left: NB, right: NB };
   208→   667→const allNoBorders = { top: NB, bottom: NB, left: NB, right: NB,
   209→   668→                       insideHorizontal: NB, insideVertical: NB };
   210→   669→
   211→   670→new Table({
   212→   671→  borders: allNoBorders,  // ← MANDATORY on every cover table
   213→   672→  // ...
   214→   673→});
   215→   674→```
   216→   675→
   217→   676→10. **Decorative lines MUST use paragraph borders, NEVER text characters**: Horizontal decorative lines (accent strips, dividers, frame edges) must be implemented with `paragraph border.top` or `border.bottom` — never with text characters like `───`, `━━━`, `═══`, or `——————`. Character-drawn lines render at inconsistent widths across MS Office and WPS (font metrics differ), causing lines to appear truncated or misaligned. Paragraph borders render pixel-perfect in both engines and their width is controlled precisely via `indent.left` / `indent.right`.
   218→   677→
   219→   678→```js
   220→   679→// ✅ Correct — paragraph border (R2 style thick accent rule)
   221→   680→new Paragraph({
   222→   681→  indent: { left: 1000, right: 1000 },
   223→   682→  border: { top: { style: BorderStyle.SINGLE, size: 18, color: P.accent, space: 20 } },
   224→   683→  children: [],
   225→   684→})
   226→   685→
   227→   686→// ❌ FORBIDDEN — text character line (renders inconsistently)
   228→   687→new Paragraph({
   229→   688→  children: [new TextRun({ text: "───────────────", color: P.accent })]
   230→   689→})
   231→   690→```
   232→   691→9. **Post-generation overflow check (mandatory)**: After building cover children, estimate total height:
   233→   692→   ```js
   234→   693→   function estimateCoverHeight(elements) {
   235→   694→     let total = 0;
   236→   695→     for (const el of elements) {
   237→   696→       if (el instanceof Table) {
   238→   697→         // Sum row heights (exact rows) or estimate 400 twips per row
   239→   698→         const rows = el.root?.[0]?.rows || [];
   240→   699→         for (const row of rows) {
   241→   700→           total += row.height?.value || 400;
   242→   701→         }
   243→   702→       } else if (el instanceof Paragraph) {
   244→   703→         const fontSize = el.root?.[0]?.size || 24; // half-pts
   245→   704→         // ★ Use pt * 11.5 (= half-pt * 10 * 1.15) for accurate single-spacing estimate
   246→   705→         const lineHeight = Math.max(fontSize * 11.5, 276); // min 276 (default 12pt)
   247→   706→         const spacingBefore = el.spacing?.before || 0;
   248→   707→         const spacingAfter = el.spacing?.after || 0;
   249→   708→         total += lineHeight + spacingBefore + spacingAfter;
   250→   709→       }
   251→   710→     }
   252→   711→     return total;
   253→   712→   }
   254→   713→   // ★ Target: estimateCoverHeight(coverChildren) < 15638 (16838 - 1200 safety)

   259→   718→### ⚠️ Cover Title Layout — calcTitleLayout() (Mandatory for ALL Recipes)
   260→   719→
   261→   720→**Every cover recipe MUST use `calcTitleLayout()` to determine title font size and line breaks.** Hardcoding font sizes or passing the full title as a single TextRun is FORBIDDEN.
   262→   721→
   263→   722→**Every paragraph with font size > body text MUST set explicit line spacing** to prevent top clipping:
   264→   723→```js
   265→   724→// ★ MANDATORY: prevent inherited small line spacing from clipping large fonts
   266→   725→spacing: { line: Math.ceil(titlePt * 23), lineRule: "atLeast", after: 100 }
   267→   726→// Example: 36pt → line: 828; 44pt → line: 1012
   268→   727→```
   269→   728→Without this, the paragraph inherits body text line spacing (e.g., 560tw), which is shorter than the font height → top of characters gets clipped.
   270→   729→
   271→   730→```js
   272→   731→/**
   273→   732→ * Calculate safe font size and smart line breaks for cover titles.
   274→   733→ * MUST be called by every recipe before building title paragraphs.
   275→   734→ *
   276→   735→ * @param {string}  title          Full title string
   277→   736→ * @param {number}  maxWidthTwips  Available width for title text (twips, after subtracting margins/padding)
   278→   737→ * @param {number}  preferredPt    Desired max font size in pt (default 40)
   279→   738→ * @param {number}  minPt          Minimum allowed font size in pt (default 24)
   280→   739→ * @returns {{ titlePt: number, titleLines: string[] }}
   281→   740→ */
   282→   741→function calcTitleLayout(title, maxWidthTwips, preferredPt = 40, minPt = 24) {
   283→   742→  // Each CJK character width ≈ pt × 20 twips
   284→   743→  const charWidth = (pt) => pt * 20;
   285→   744→  const charsPerLine = (pt) => Math.floor(maxWidthTwips / charWidth(pt));
   286→   745→
   287→   746→  // Try from preferredPt downward until title fits in ≤ 3 lines
   288→   747→  let titlePt = preferredPt;
   289→   748→  let lines;
   290→   749→  while (titlePt >= minPt) {
   291→   750→    const cpl = charsPerLine(titlePt);
   292→   751→    if (cpl < 2) { titlePt -= 2; continue; }
   293→   752→    lines = splitTitleLines(title, cpl);
   294→   753→    if (lines.length <= 3) break;
   295→   754→    titlePt -= 2;
   296→   755→  }
   297→   756→
   298→   757→  // If still > 3 lines at minPt, force 3 lines
   299→   758→  if (!lines || lines.length > 3) {
   300→   759→    const cpl = charsPerLine(minPt);
   301→   760→    lines = splitTitleLines(title, cpl);
   302→   761→    titlePt = minPt;
   303→   762→  }
   304→   763→
   305→   764→  return { titlePt, titleLines: lines };
   306→   765→}
   307→   766→
   308→   767→/**
   309→   768→ * Smart Chinese title line-breaking — breaks at semantic boundaries, never mid-word.
   310→   769→ *
   311→   770→ * Rules:
   312→   771→ * 1. Prefer breaking after particles, punctuation, connectors, underscores, spaces
   313→   772→ * 2. Never split a compound word (e.g., "管理规范" must not become "管理规" + "范")
   314→   773→ * 3. No single-character orphan on the last line — merge into previous line
   315→   774→ * 4. If no good break point found within 60-130% of charsPerLine, break at charsPerLine
   316→   775→ *
   317→   776→ * @param {string} title        Full title string
   318→   777→ * @param {number} charsPerLine Max characters per line at current font size
   319→   778→ * @returns {string[]}          Array of line strings
   320→   779→ */
   321→   780→function splitTitleLines(title, charsPerLine) {
   322→   781→  if (title.length <= charsPerLine) return [title];
   323→   782→
   324→   783→  // Characters that are safe break points (break AFTER these)
   325→   784→  const breakAfter = new Set([
   326→   785→    ...'，。、；：！？',              // CJK punctuation
   327→   786→    ...'的与和及之在于为',            // CJK particles/prepositions
   328→   787→    ...'-_—–·/',                     // connectors
   329→   788→    ...' \t',                         // whitespace
   330→   789→  ]);
   331→   790→
   332→   791→  const lines = [];
   333→   792→  let remaining = title;
   334→   793→
   335→   794→  while (remaining.length > charsPerLine) {
   336→   795→    let breakAt = -1;
   337→   796→
   338→   797→    // Search backward from charsPerLine to 60% for a break point
   339→   798→    for (let i = charsPerLine; i >= Math.floor(charsPerLine * 0.6); i--) {
   340→   799→      if (i < remaining.length && breakAfter.has(remaining[i - 1])) {
   341→   800→        breakAt = i;
   342→   801→        break;
   343→   802→      }
   344→   803→    }
   345→   804→
   346→   805→    // If not found, search forward up to 130%
   347→   806→    if (breakAt === -1) {
   348→   807→      const limit = Math.min(remaining.length, Math.ceil(charsPerLine * 1.3));
   349→   808→      for (let i = charsPerLine + 1; i < limit; i++) {
   350→   809→        if (breakAfter.has(remaining[i - 1])) {
   351→   810→          breakAt = i;
   352→   811→          break;
   353→   812→        }
   354→   813→      }
   355→   814→    }
   356→   815→
   357→   816→    // Last resort: break at charsPerLine, but avoid splitting compound CJK words
   358→   817→    if (breakAt === -1) {
   359→   818→      breakAt = charsPerLine;
   360→   819→      // If both chars at the break boundary are CJK (likely a compound word),
   361→   820→      // step back 1 char to keep the word together
   362→   821→      const prevChar = remaining[breakAt - 1];
   363→   822→      const nextChar = remaining[breakAt];
   364→   823→      if (prevChar && nextChar &&
   365→   824→          !breakAfter.has(prevChar) && !breakAfter.has(nextChar) &&
   366→   825→          /[\u4e00-\u9fff]/.test(prevChar) && /[\u4e00-\u9fff]/.test(nextChar)) {
   367→   826→        breakAt = breakAt - 1;
   368→   827→      }
   369→   828→    }
   370→   829→
   371→   830→    lines.push(remaining.slice(0, breakAt).trim());
   372→   831→    remaining = remaining.slice(breakAt).trim();
   373→   832→  }
   374→   833→  if (remaining) lines.push(remaining);
   375→   834→
   376→   835→  // Prevent single-character orphan on last line — merge into previous
   377→   836→  if (lines.length > 1 && lines[lines.length - 1].length <= 2) {
   378→   837→    const last = lines.pop();
   379→   838→    lines[lines.length - 1] += last;
   380→   839→  }
   381→   840→
   382→   841→  return lines;
   383→   842→}
   384→   843→
   385→   844→/**
   386→   845→ * Calculate dynamic spacing values for cover elements to fit within page height.
   387→   846→ *
   388→   847→ * @param {object} params
   389→   848→ * @param {number} params.titleLineCount   Number of title lines
   390→   849→ * @param {number} params.titlePt          Title font size in pt
   391→   850→ * @param {boolean} params.hasSubtitle     Whether subtitle exists
   392→   851→ * @param {boolean} params.hasEnglishLabel Whether English label exists
   393→   852→ * @param {number} params.metaLineCount    Number of meta info lines
   394→   853→ * @param {number} params.fixedHeight      Sum of fixed-height elements (color strips, accent bars, footer) in twips
   395→   854→ * @param {number} params.pageHeight       Total page height in twips (default 16838)
   396→   855→ * @returns {{ topSpacing, midSpacing, bottomSpacing }}  Spacing values in twips
   397→   856→ */
   398→   857→function calcCoverSpacing(params) {
   399→   858→  const {
   400→   859→    titleLineCount = 1, titlePt = 36, hasSubtitle = false,
   401→   860→    hasEnglishLabel = false, metaLineCount = 0,
   402→   861→    fixedHeight = 800, pageHeight = 16838,
   403→   862→    marginTop = 0, marginBottom = 0,   // ★ NEW: pass actual section margins
   404→   863→  } = params;
   405→   864→
   406→   865→  // ★ Safety margin: 1200 twips (cross-engine: MS Office renders large fonts
   407→   866→  // taller than calculated; extra 400tw buffer prevents footer clipping)
   408→   867→  const SAFETY = 1200;
   409→   868→  // ★ Subtract page margins from available height (cover section may have margins)
   410→   869→  const usableHeight = pageHeight - marginTop - marginBottom - SAFETY;
   411→   870→
   412→   871→  // ★ Accurate height estimation per element:
   413→   872→  const titleHeight = titleLineCount * (titlePt * 23 + 200);
   414→   873→  const subtitleHeight = hasSubtitle ? (12 * 23 + 600) : 0;
   415→   874→  const englishLabelHeight = hasEnglishLabel ? (9 * 23 + 600) : 0;
   416→   875→  const metaHeight = metaLineCount * (10 * 23 + 100);
   417→   876→
   418→   877→  // ★ Account for implicit paragraph heights:
   419→   878→  const implicitParaHeight = 3 * 300;
   420→   879→
   421→   880→  const contentHeight = titleHeight + subtitleHeight + englishLabelHeight +
   422→   881→                        metaHeight + fixedHeight + implicitParaHeight;
   423→   882→
   424→   883→  const remainingSpace = usableHeight - contentHeight;
   425→   884→  const safeRemaining = Math.max(remainingSpace, 400);
   426→   885→
   427→   886→  // ★ Footer protection: bottomSpacing must be ≥ FOOTER_MIN to prevent
   428→   887→  // footer + accent line from being clipped at the cell bottom edge
   429→   888→  const FOOTER_MIN = 800;
   430→   889→  const rawTop = Math.floor(safeRemaining * 0.45);
   431→   890→  const rawBottom = Math.floor(safeRemaining * 0.45);
   432→   891→  const bottomSpacing = Math.max(rawBottom, FOOTER_MIN);
   433→   892→  const topSpacing = Math.max(rawTop - Math.max(0, FOOTER_MIN - rawBottom), 400);
   434→   893→  const midSpacing = Math.max(safeRemaining - topSpacing - bottomSpacing, 0);
   435→   894→
   436→   895→  return { topSpacing, midSpacing, bottomSpacing };
   437→   896→}
   438→   897→```

   467→   926→### ⚠️ CRITICAL — Cover Section Non-Negotiables (ALL Recipes)
   468→   927→
   469→   928→These 3 properties are MANDATORY for every cover implementation (R1–R7). Omitting ANY of them causes cover layout failure:
   470→   929→
   471→   930→1. **Cover section margin = 0**: The cover MUST be in its own section with `page.margin: { top: 0, bottom: 0, left: 0, right: 0 }`. Non-zero margins shrink the wrapper away from page edges → white gaps around the cover ("cover not filling the page"). This is the #1 cause of broken cover layouts.
   472→   931→
   473→   932→2. **Wrapper row exact height**: The outer wrapper table row MUST set `height: { value: 16838, rule: "exact" }`. Without this, content overflow pushes to page 2, or insufficient content leaves bottom whitespace.
   474→   933→
   475→   934→3. **Wrapper table borders = allNoBorders**: MUST explicitly set `borders: allNoBorders`. Default docx-js borders add ~8 twips per edge. MS Office includes border thickness in exact-height calculation → total exceeds 16838 → blank page 2 (WPS is lenient, MS Office is strict).
   476→   935→
   477→   936→**Cover section template (copy this for every Recipe):**
   478→   937→```js
   479→   938→sections: [
   480→   939→  {
   481→   940→    // ⚠️ Cover section — margin MUST be 0, separate from body
   482→   941→    properties: {
   483→   942→      page: {
   484→   943→        size: { width: 11906, height: 16838 },
   485→   944→        margin: { top: 0, bottom: 0, left: 0, right: 0 },
   486→   945→      },
   487→   946→    },
   488→   947→    children: buildCoverRX(config), // ← replace with actual recipe function
   489→   948→  },
   490→   949→  {
   491→   950→    // Body section — normal margins
   492→   951→    properties: {
   493→   952→      type: SectionType.NEXT_PAGE,
   494→   953→      page: {
   495→   954→        size: { width: 11906, height: 16838 },
   496→   955→        margin: { top: 1440, bottom: 1440, left: 1701, right: 1417 },
   497→   956→      },
   498→   957→    },
   499→   958→    children: [...bodyContent],
   500→   959→  },
   501→   960→]
   502→   961→```

   509→   968→**Use case:** Annual report, business report, tech proposal (most versatile premium recipe)

   541→  1000→    metaLineCount: (config.metaLines || []).length,
